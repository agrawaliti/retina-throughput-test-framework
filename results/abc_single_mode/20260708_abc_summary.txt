A/B/C SINGLE-MODE TEST — Retina buffer mode throughput + metric verification
============================================================================
Date (UTC):     2026-07-08
Subscription:   Azure Network Agent - Standalone Test
Region:         westus2 (existing benchmark clusters reused)
Hardware:       AKS, Standard_D32s_v3 (32 vCPU) benchmark nodes, 1 sender + 1 receiver each

NOTE ON HARDWARE CHOICE
  Requested target was HX176rs in southeastasia (quota = 352 HX vCPUs = exactly
  2x Standard_HX176rs). Because HX176rs are very expensive HPC VMs and no cost
  approval was available, the A/B/C was run on the existing, already-validated
  westus2 D32s_v3 clusters instead. Each cluster is pinned to exactly one mode
  on identical hardware, so this is equivalent to a single-cluster sequential
  A/B/C without the cost/time of provisioning HPC nodes.
    A = retina-bench-noretina    (no Retina)
    B = retina-bench-baseline    (Retina, perf-array: packetParserRingBuffer=disabled)
    C = retina-bench-withretina  (Retina, ring-buffer: packetParserRingBuffer=enabled)
  Both Retina clusters: enabledPlugin=[dropreason,packetforward,linuxutil,dns,
  packetparser], enablePodLevel=true, enableAnnotations=true,
  dataAggregationLevel=low, agent CPU request 500m (no limit).

WORKLOAD
  Go reuseport TCP blast. Receiver: 31 SO_REUSEPORT listeners + 124 reader
  goroutines (GOMAXPROCS=31). Sender: 15 pods x 165 conns = 2475 flows.
  Metric = median receiver Gbps. Source sweep: results/buffer_crossover/
  20260708T112425Z_three_cluster_summary.csv (90s/payload, all clusters
  measured in the same time window).

  * small-payload row is the 1024B point from the sweep.
  Observations:
    - Retina cost is packet-rate driven: worst at small payloads (high pps),
      negligible at 64KB (link saturates, few packets).
    - Ring-buffer (C) > perf-array (B) at small/mid payloads; converge at 64KB.
